# Silsbee Fleet Group — WordPress Dev Environment

## Project

WordPress development environment for **Silsbee Fleet Group** (silsbeefleet.com), a Ford fleet/government vehicle dealer based in Silsbee, TX. The stack runs locally on WSL Ubuntu 24.04 via Docker Compose and uses the **Autovault** automotive theme with **Elementor Pro** as the page builder.

---

## Stack

| Service      | Image               | Host Port | Purpose               |
|--------------|---------------------|-----------|-----------------------|
| `wordpress`  | wordpress:latest    | 8080      | WP + Apache           |
| `db`         | mysql:8.4           | internal  | Database              |
| `phpmyadmin` | phpmyadmin:latest   | 8081      | DB admin UI           |

- Network: `sbf_internal` (private bridge — MySQL never exposed to host)
- Volume: `sbf_db_data` → `/var/lib/mysql` (named, persists across restarts)
- WordPress files: `./wordpress` bind-mounted to `/var/www/html` (editable locally)


## Theme: Autovault

- **Name**: Autovault
- **Version**: 1.0.2
- **Author**: reactheme (reactheme.com)
- **Parent theme**: `autovault` | **Active theme**: `autovault-child`
- **WooCommerce**: supported (`inc/woocommerce-functions.php`)
- **Customizer**: Kirki framework (`inc/kirki_customizer.php`)

Key files in the parent theme:

| File | Purpose |
|------|---------|
| `functions.php` | Theme bootstrap, hooks, supports |
| `inc/theme-functions.php` | Core helper functions |
| `inc/theme-scripts.php` | Enqueue CSS/JS |
| `inc/kirki_customizer.php` | Customizer panel options |
| `assets/scss/theme.scss` | Main stylesheet source |
| `assets/css/responsive.css` | Breakpoint overrides |
| `inc/tgm/tgm-config.php` | Required plugin declarations |
| `inc/demo-data/` | Demo import XML/JSON files |

**Always edit in `autovault-child/`**, not the parent. The child theme inherits all parent styles and overrides only what it declares.

---

## Plugin: Elementor Pro

- **Version**: 4.0.1
- **Requires**: Elementor (free) plugin + license key on first activation
- **PHP**: ≥ 7.4 | **WordPress**: ≥ 6.7
- **Location**: `wordpress/wp-content/plugins/elementor-pro/`

On first run: activate the free **Elementor** plugin first, then activate **Elementor Pro** and enter the license key under Elementor → License.

## Common Commands

```bash
# Start the stack
docker compose up -d

# Stop (data preserved)
docker compose down

# Destroy everything including DB volume
docker compose down -v

# Follow all logs
docker compose logs -f

# Follow a single service
docker compose logs -f wordpress

# Open MySQL shell
docker compose exec db mysql -u root -p

# Restart just WordPress
docker compose restart wordpress
```

---

## Hot Reload

PHP is interpreted on every request — **no container restart is needed** when editing files. Workflow:

1. Edit any file under `./wordpress/` (theme, plugin, template)
2. Save the file
3. Refresh the browser → changes are live

CSS/SCSS changes compiled outside Docker also reflect immediately on browser refresh. No watcher or rebuild step required for PHP/template changes.

## First-Run Checklist

- [ ] `cp .env.example .env` and set all passwords
- [ ] `docker compose up -d`
- [ ] Wait ~30 s, then open http://localhost:8080
- [ ] Complete the WordPress 5-minute install wizard
- [ ] **wp-admin → Plugins**: activate **Elementor** (free), then **Elementor Pro** + enter license
- [ ] **wp-admin → Appearance → Themes**: activate **Autovault Child**
- [ ] (Optional) Import demo data: **wp-admin → Tools → Import** using `autovault/inc/demo-data/`
